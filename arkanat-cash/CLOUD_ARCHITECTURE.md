# معمارية النسخة المشتركة المستقلة منطقياً

## القرار التنفيذي
تم تشغيل البوابة على البنية الحالية ضمن اشتراك **Arkanat Org** لتجنب أي تكلفة شهرية إضافية. لم يتم إنشاء مشروع Supabase ثالث.

## الفصل عن الأنظمة الأخرى
تستخدم البوابة جداول مستقلة بالكامل:
- cash_portal_access
- cash_requests
- cash_transactions
- cash_imports
- cash_audit_log

لا يوجد أي Foreign Key أو مزامنة أو Trigger يربط هذه الجداول بجداول Guard ERP أو Guard Control أو الموارد البشرية أو الرواتب أو العمليات.

## الوصول والأمان
- GitHub Pages يستضيف الواجهة فقط.
- قاعدة البيانات لا تسمح بالوصول المجهول إلى بيانات العهد.
- Supabase Auth مسؤول عن تسجيل الدخول.
- cash_portal_access هو Allowlist مستقل للمستخدمين المصرح لهم.
- RLS مفعّل على جميع الجداول.
- المفتاح الموجود في الواجهة Publishable Key فقط؛ لا يوجد Service Role Key داخل GitHub.

## المزامنة
بعد تسجيل الدخول:
1. تُحمّل البيانات المشتركة من Supabase.
2. كل تعديل محلي يُحفظ فوراً في المتصفح ثم تتم مزامنته إلى القاعدة.
3. يمكن استخدام زر التخزين/التحديث لسحب آخر نسخة مشتركة.
4. إذا كانت القاعدة المشتركة فارغة ويوجد على الجهاز سجل محلي سابق، تعرض البوابة ترحيل البيانات مرة واحدة بعد موافقة المستخدم.

## التكلفة
هذا التصميم يعيد استخدام مشروع Supabase قائم ضمن الخطة الحالية، لذلك لا ينشئ Compute Project جديداً ولا يضيف رسوم المشروع الإضافي التي ظهرت عند تقييم إنشاء مشروع ثالث.
